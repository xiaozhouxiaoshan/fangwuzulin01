## 5.2.1 管理员功能模块

管理员功能的入口是统一登录页。前端登录组件要求用户先选择角色，再输入用户名和密码。这样做的目的不是单纯区分界面，而是让系统在发起认证请求前就明确本次登录所对应的数据表。登录成功后，前端将 Token、角色名和会话表名写入本地存储，并跳转至后台首页。管理员登录过程的关键代码如下：

```javascript
login() {
  let menus = this.menus;
  for (let i = 0; i < menus.length; i++) {
    if (menus[i].roleName == this.rulesForm.role) {
      this.tableName = menus[i].tableName;
    }
  }

  this.$http({
    url: `${this.tableName}/login?username=${this.rulesForm.username}&password=${this.rulesForm.password}`,
    method: "post"
  }).then(({ data }) => {
    if (data && data.code === 0) {
      this.$storage.set("Token", data.token);
      this.$storage.set("role", this.rulesForm.role);
      this.$storage.set("sessionTable", this.tableName);
      this.$storage.set("adminName", this.rulesForm.username);
      this.$router.replace({ path: "/index/" });
    }
  });
}
```

对应源码：`front/src/views/login.vue:108`

管理员身份在后端由 `users` 接口完成校验。系统先按用户名查询管理员记录，再生成 Token，并把角色信息写入令牌记录。这个过程构成了后台权限控制的基础。

```java
@IgnoreAuth
@PostMapping(value = "/login")
public R login(String username, String password, String captcha, HttpServletRequest request) {
    UserEntity user = userService.selectOne(new EntityWrapper<UserEntity>().eq("username", username));
    if(user==null || !user.getPassword().equals(password)) {
        return R.error("账号或密码不正确");
    }
    String token = tokenService.generateToken(user.getId(),username, "users", user.getRole());
    return R.ok().put("token", token);
}
```

## 5.2.2 房主功能模块

房主功能模块的实现重点在于“房源供给方如何围绕自己发布的房源进行全流程管理”。房主登录逻辑与用户、管理员相似，但认证表切换为 `fangzhu`，字段从通用用户名改为房主账号。系统通过这种表级映射，保证不同角色登录时进入正确的数据空间。

```java
@IgnoreAuth
@RequestMapping(value = "/login")
public R login(String username, String password, String captcha, HttpServletRequest request) {
    FangzhuEntity user = fangzhuService.selectOne(
        new EntityWrapper<FangzhuEntity>().eq("fangzhuzhanghao", username)
    );
    if(user==null || !user.getMima().equals(password)) {
        return R.error("账号或密码不正确");
    }
    
    String token = tokenService.generateToken(user.getId(), username,"fangzhu",  "房主" );
    return R.ok().put("token", token);
}
```

对应源码：`back/src/main/java/com/controller/FangzhuController.java:57`

房主登录后可以管理自己发布的房屋信息。系统没有专门为房主单独开发另一套房屋管理控制器，而是在同一个房屋信息接口中依据会话角色追加过滤条件。这样，房主访问房源列表时，系统自动限制为“只显示当前房主账号对应的房源”。这是一种典型的同接口多角色复用方式。

论文在这一部分可以进一步强调房主视角的业务连续性。房主不是只发布房源后等待结果，而是贯穿预约、合同和租后服务。预约模块中，房主能够查看房屋名称、预约时间、租客姓名、联系电话以及审核状态；合同模块则记录合同名称、租用月数、合同金额和支付状态；进入居住期后，房主还需要处理房屋报修与维修反馈。这种从房源发布到租后维护的连续流程，是房主功能模块区别于普通信息发布系统的地方。

## 5.3 用户功能模块

用户模块对应论文中的租客视角。租客既可以在前台浏览房源，也可以在后台查看预约、合同、报修和收藏记录，因此这一部分最适合体现系统的业务闭环。

用户登录后的请求会统一经过 Axios 拦截器。拦截器在请求头附加 Token，在响应中识别 401 状态并跳转回登录页。这样，用户在浏览房源、提交预约或查看合同信息时，不需要在每个页面单独处理身份状态。

```javascript
http.interceptors.request.use(config => {
    config.headers['Token'] = storage.get('Token')
    return config
}, error => {
    return Promise.reject(error)
})

http.interceptors.response.use(response => {
    if (response.data && response.data.code === 401) {
        router.push({ name: 'login' })
    }
    return response
}, error => {
    return Promise.reject(error)
})
```

对应源码：`front/src/utils/http.js:13`

租客浏览房源时，前端页面会展示房屋名称、类型、状态、小区、月租价格、押金、房主账号和房主姓名，并在操作列开放“预约”按钮。由此，房源浏览和预约申请被整合在同一业务界面中，用户不需要切换到独立表单页才能发起预约。

报修信息中常常包含图片等附件，因此文件上传接口也是用户模块论述中值得保留的一段代码。系统在接收上传请求后，先校验文件是否为空，再提取扩展名并生成新的文件名，最终将文件保存到后端静态资源目录。这使租客在提交报修时能够附带现场图片，提高问题描述的完整性。

```java
@RequestMapping("/upload")
public R upload(@RequestParam("file") MultipartFile file,String type) throws Exception {
    if (file.isEmpty()) {
        throw new EIException("上传文件不能为空");
    }
    String fileExt = file.getOriginalFilename().substring(file.getOriginalFilename().lastIndexOf(".")+1);
    File path = new File(ResourceUtils.getURL("classpath:static").getPath());
    File upload = new File(path.getAbsolutePath(),"/upload/");
    if(!upload.exists()) {
        upload.mkdirs();
    }
    String fileName = new Date().getTime()+"."+fileExt;
    File dest = new File(upload.getAbsolutePath()+"/"+fileName);
    file.transferTo(dest);
    return R.ok().put("file", fileName);
}
```

对应源码：`back/src/main/java/com/controller/FileController.java:48`
